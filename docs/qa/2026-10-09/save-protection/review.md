# 저장 보호 기반 구현 검증

2026-10-09 · 신규 설계 R0의 첫 구현 단위. 로컬 개발 브라우저 검증이며 공개 배포는 수행하지 않았다.

## 구현 결과

- 저장 성공/실패와 실패 이유를 반환하고 모든 기존 saveState 호출에서 상태 안내를 공유한다.
- schemaVersion 1 및 저장 revision을 기록하고 hydrate에서 복원한다. revision은 저장 성공 시에만 증가한다.
- 구 저장을 최초 이행할 때 `claude_game_save_v1_legacy_backup`에 원본 문자열을 보존한다. 백업 실패 시 본 저장을 변경하지 않는다.
- 손상 JSON·배열·null·미지원 버전·잘못된 revision은 읽기 실패로 분리하고 덮어쓰기를 거부한다. 시작 시 해당 기록이나 저장 접근 오류가 있으면 게임을 시작하지 않는다.
- 이미 다른 revision이 저장된 경우 오래된 메모리 상태의 쓰기를 거부한다.
- 게임 중 저장 실패 안내는 반복 호출에도 하나만 표시하고 재시도 성공 시 숨긴다. native dialog가 열리면 안내를 dialog 안으로 이동해 버튼 접근성을 유지한다.

## 확인 결과

최초 재현에서 신규 테스트 11개가 실패했고 구현 후 전체 Vitest 20파일 / 132개가 통과했다. 저장 실패 후 원본 보존·revision 유지, 구 저장 이행·진행 보존, 백업 실패, 손상/미지원 버전 보존, 순차적인 다른 작성자 변경 감지를 포함한다.

[Playwright 결과](results.json): 구 저장 백업/재접속, 저장 실패 3회 뒤 안내 1개, Enter 키 재시도, 모달 안 재시도, 미지원/손상/접근불가 시작 차단을 확인했다. 320×568, 390×844, 768×1024, 1440×900에서 안내가 화면 경계를 넘지 않았다. 페이지 오류 0개. 주요 모바일·시작 차단·모달 캡처를 열어 직접 확인했다.

처음 브라우저 fixture는 개발 서버의 모듈을 직접 import해 앱 구독과 분리되는 현상이 있었다. 실제 앱의 개발 전용 저장 핸들로 실행하도록 바꿨다. 실패 결과는 나왔지만 안내 DOM이 그대로였다는 증거는 `failure-state.json`의 최종 통과 실행 결과로 대체됐다. 또 자동 저장이 재시도 클릭 전에 성공해 안내를 숨기는 경쟁은 실패 주입을 클릭 직전까지 유지하도록 fixture를 수정했다.

## 남은 범위

이 변경은 저장 실패 시 이미 변경된 게임 메모리 상태를 원상 복구하지 않는다. 비용 차감·보상 지급·수령 상태를 같은 후보에 적용하고 저장 후 공개하는 거래 계층은 R1에서 구현해야 한다. 현재 상자 가방 초과 환산 정책도 그대로다.

revision 비교는 순차적인 오래된 쓰기를 거절하지만 여러 탭의 읽기-변경-쓰기 전체를 잠그지 않는다. 동시 쓰기, 구버전 앱의 무조건 쓰기, 전원 장애 내구성은 보장하지 않는다. Web Locks 등의 작성자 정책과 새 상태 필드 이행도 후속 범위다. 손상 기록의 다운로드/복구 UI는 아직 없으며 자동 삭제하지 않는다.

실제 모바일 기기 성능, 사용자 이해도, 공개 배포 브라우저는 이번 검증 대상이 아니다. 기존 번들 500KB 초과 경고는 남아 있다.
